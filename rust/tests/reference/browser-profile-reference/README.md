# Fixed browser profile first-flight reference

This independent test tool uses the existing pinned uTLS v1.8.7 module and
sing-box ALPN wrapper logic. It captures Chrome133, Android11, Firefox120,
Safari16.0, iOS14, Edge85, QQ11.1 and3607.5. It is not linked into the Rust
kernel. The existing Chrome/Android fixture is not changed.

Status: source prepared; Go build/capture/Go self-tests have not run. Python
normalization tests can be checked independently against the28 existing
Chrome/Android captures; that is not evidence for the new six profiles.

After the parent schedules the shared build lock:

```sh
python3 scripts/run-bounded-build.py -- python3 tests/reference/browser-profile-reference/capture.py --test
```

The script also supports `--root /absolute/source-or-overlay-root` while staged,
`--output-dir` and `--profiles edge,qq`. It uses CGO_ENABLED=0, one Go scheduler
and build job, offline pinned dependencies, a256MiB Go heap target, and writes
new captures only under the selected target evidence directory.

Every profile has10 base cases: default DNS, no SNI with a separate verification
name, IPv4, custom ALPN, direct ALPN[h2], setter-equivalent ALPN[h2,http/1.1], and
valid DNS names of length63/127/191/253. For profiles that have a padding object,
it also targets unpadded ClientHello lengths255/256/507/508/511/512 by varying
only SNI. It records unreachable targets explicitly when they would require
an invalid DNS length. It never pads by inserting a fake extra extension.

Padding may be absent even when its template object exists. BoringPaddingStyle
only serializes for256..511 bytes; near512 it emits at least one padding byte.
The tool records actual pre/post padding lengths and checks each attainable
target against generated bytes. Firefox/Chrome/Android/360 do not receive
invented padding objects. Chrome shuffled extension order is retained.

`captures.json` contains complete bytes written to a fake socket and the built
ClientHello, requested/effective configuration, actual extension object names,
padding metadata, and the expected EOF handshake error. `handshake_complete`
must be false. This proves construction only, not server authentication or
completion of any advertised weak suite/extension.

`normalize.py` strictly decodes record and handshake/vector lengths, preserves
all records and complete normalized hex, preserves unknown extension payloads,
all cipher/signature/group/extension order and duplicate values, SNI/ALPN,
compression, all lengths, and SEC1 point-format prefixes. It zeros random,
session ID, real ephemeral public-key bytes and ECH random material. GREASE
values are replaced by canonical GREASE values while preserving their equality
classes across cipher/groups/versions/key_share/extensions. It also records
whether the hybrid X25519 component equals the independent share. ECH type,
KDF/AEAD, encapsulated-key and payload lengths are retained.

`go test` checks the80 base first flights and valid DNS generation. Python tests
check malformed/truncated vectors, unknown extensions, GREASE relationships,
padding, and the existing28 fixed captures. Full Edge/QQ/Rust wire comparisons
and successful mixed-version handshakes remain the parent's next validation.
Random/randomized seed generation is deliberately outside this fixed-template
capture tool; the preceding audit documents those separate semantics.
